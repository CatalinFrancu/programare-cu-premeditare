\chapter{Elemente de teoria numerelor}

\section{Exponențiere binară}

Consider acest subiect ca fiind de bază. Dacă aveți nelămuriri, căutați resurse pe Internet, de exemplu pe \href{https://cp-algorithms.com/algebra/binary-exp.html}{CP Algorithms}. Reiau aici doar codul:

\begin{minted}{c}
const int MOD = 1'000'000'007;

int bin_exp(int b, int e) {
  int result = 1;

  while (e) {
    if (e & 1) {
      result = (long long)result * b % MOD;
    }
    b = (long long)b * b % MOD;
    e >>= 1;
  }

  return result;
}
\end{minted}

\subsection{Mica teoremă a lui Fermat}

Pentru orice număr prim $p$ și orice $a$ cu $0 \leq a < p$,

$$a^{p-1} \equiv 1 \pmod{p}$$

De aici rezultă și că putem reduce exponentul modulo $p-1$:

$$a^e \equiv a^{e \mod p - 1} \mod p$$

Vom folosi această teoremă în secțiunile următoare pentru a calcula inverse modulare.

\subsection{Exponențiere în \texorpdfstring{$\bigoh(1)$}{O(1)} cu precalculare în \texorpdfstring{$\bigoh(\sqrt{n})$}{O(sqrt(n)}}

Dacă exponențierea este operația critică (adică dacă avem foarte des nevoie de ea), o putem accelera la $\bigoh(1)$ printr-o descompunere în radical. Am avut această nevoie la problema \href{https://kilonova.ro/problems/637}{Ashima} (Lot juniori 2023).

\begin{minted}{c}
const int MOD = 1'000'000'007;
const int BITS = 15;
const int ROOT = 1 << BITS;

// pow2: 2^0, 2^1, 2^2, ..., 2^32767
// pow2_large: 2^0, 2^32768, 2^65536, 2^98304, ... 2^(32768*32767)
int pow2[ROOT];
int pow2_large[ROOT];

void precompute_powers_of_2() {
  pow2[0] = 1;
  for (int i = 1; i < ROOT; i++) {
    pow2[i] = pow2[i - 1] * 2 % MOD;
  }

  pow2_large[0] = 1;
  pow2_large[1] = (2 * pow2[ROOT - 1]) % MOD;
  for (int i = 2; i < ROOT; i++) {
    pow2_large[i] = (long long)pow2_large[i - 1] * pow2_large[1] % MOD;
  }
}

int power_of_2(long long e) {
  e %= (MOD - 1); // Mica teoremă a lui Fermat.

  long long small = pow2_large[e >> BITS];
  long long large = pow2[e & (ROOT - 1)];
  int result = small * large % MOD;

  return result;
}
\end{minted}

Codul calculează în $\bigoh(1)$ valori $2^e$ pentru $e < 2^{30}$. Metoda este să îl scriem pe $e = 2^{15} \cdot f + g$. Atunci:

$$2^e = 2^{2^{15} \cdot f + g} = (2^{2^{15}})^f \cdot 2^g$$

În prealabil, codul precalculează $2^i$ și $(2^{2^{15}})^i$ pentru $0 \leq i < 2^{15}$, ceea ce conduce la timp constant.

\subsection{Aplicație: Suma unei progresii geometrice}

Date fiind $a$, $n$ și modulul $M$, să calculăm $S_n = 1 + a + a^2 + \dots + a^{n-1} \mod M$.

Știm deja că putem rescrie:

$$S_n = \frac{a^n - 1}{a - 1}$$

și deci putem răspunde la întrebare printr-o exponențiere rapidă și un invers modular (vom vorbi în curînd despre inverse modulare). Dar dacă modulul nu este prim, atunci inversul modular poate fi nedefinit. De aceea, să căutăm o soluție care apelează doar la înmulțiri.

\subsubsection*{Implementare recursivă v1}

Dacă $n$ este par, putem scrie recurența:

\begin{align*}
S_n &= (1 + a + a^2 + \dots + a^{\frac{n}{2}-1}) + (a^\frac{n}{2} + \dots + a^{n-1}) \\
&= (1 + a^\frac{n}{2}) (1 + a + a^2 + \dots + a^{\frac{n}{2}-1}) \\
&= (1 + a^\frac{n}{2}) S_{\frac{n}{2}}
\end{align*}

Dacă $n$ este impar, putem reduce problema la una cu $n$ par:

\begin{align*}
S_n &= 1 + a(1 + a + a^2 + \dots + a^{n-2}) \\
&= 1 + a \cdot S_{n-1}
\end{align*}

De aici rezultă imediat codul:

\begin{minted}{c}
int s(int a, int n) {
  if (n == 1) {
    return 1;
  }

  if (n & 1) {
    int rec = s(a, n - 1);
    return (1 + (long long) a * rec) % MOD;
  } else {
    long long mult = 1 + bin_exp(a, n / 2);
    return mult * s(a, n / 2) % MOD;
  }
}
\end{minted}

Problema cu acest cod este că are complexitatea $\bigoh(\log^2 n)$, căci face $\bigoh(\log n)$ exponențieri rapide.

\subsubsection*{Implementare recursivă v2}

Putem scăpa de exponențieri dacă îi cerem funcției reapelate să ne returneze și $a^{\frac{n}{2}}$. În acest caz, vă rog să evitați să returnați două valori din funcție (cum ar fi să pasați două argumente prin referință). Implementarea curată încapsulează cele două valori de returnat într-un \ccode{struct}.

\begin{minted}{c}
struct prog {
  long long term; // stochează a^n pentru un n oarecare
  long long sum;  // stochează 1 + a + ... + a^{n-1} pentru același n
};

prog s(int a, int n) {
  if (n == 1) {
    return { a, 1 };
  }

  if (n & 1) {
    prog p = s(a, n - 1);
    return {
      p.term * a % MOD,
      (1 + a * p.sum) % MOD,
    };
  } else {
    prog p = s(a, n / 2);
    return {
      p.term * p.term % MOD,
      (1 + p.term) * p.sum % MOD,
    };
  }
}
\end{minted}

\subsubsection*{Implementare iterativă}

De amorul artei, să căutăm și o soluție iterativă, similară cu cea pentru exponențierea rapidă. În limbaj natural, exponențierea rapidă enumeră puterile $a, a^2, a^4, a^8 \dots$ și le înmulțește pe cele care compun reprezentarea binară a lui $n$. De exemplu, $a^{42} = a^2 \cdot a^8 \cdot a^{32}$.

Să luăm un exemplu mare, ca să punem în evidență recurența: $n = 364 = 101101100_{(2)}$. Vă recomand și vouă această abordare: nu vă alegeți doar exemple cu $n = 3$. Durează mai mult să scrii un exemplu mai mare, dar soluția iese imediat în evidență.

\begin{align*}
S_{364} &= (1 + a^{182}) \cdot S_{182} \\
S_{182} &= (1 + a^{91}) \cdot S_{91} \\
S_{91} &= 1 + a [(1 + a^{45}) \cdot S_{45}] \\
S_{45} &= 1 + a \cdot [(1 + a^{22}) \cdot S_{22}] \\
S_{22} &= (1 + a^{11}) \cdot S_{11} \\
S_{11} &= 1 + a \cdot [(1 + a^{5}) \cdot S_{5}] \\
S_{5} &= 1 + a \cdot [(1 + a^{2}) \cdot S_{2}] \\
S_{2} &= (1 + a^{1}) \cdot S_{1} \\
S_{1} &= 1 \\
\end{align*}

Dacă privim lista de indici calculați (1, 2, 5, 11, 22, 45, 91, 182, 364), observăm că acestea sînt exact prefixele lui 364 în baza 2. Deci trebuie să construim termenii lui $S$ de la mic la mare, iterînd prin biții lui $S$ de la stînga la dreapta (invers decît la exponențierea binară). Nu strică să specificăm un contract despre ce stochează iterația curentă, așa cum se vede în codul de mai jos.

\begin{minted}{c}
int s(int a, int n) {
  int num_bits = 32 - __builtin_clz(n);
  long long sum = 0;
  long long ak = 1;

  for (int i = 0; i < num_bits; i++) {
    // Contract: fie k numărul format din primii i biți ai lui n.
    // Atunci la această linie ak = a^k și sum = 1 + a + ... + a^{k-1}.
    // Din vechiul ak (deci a^{k/2}) calculăm noul sum.
    sum = (1 + ak) * sum % MOD;
    ak = ak * ak % MOD;

    int bit = (n >> (num_bits - i - 1)) & 1;
    if (bit) {
      sum = (1 + a * sum) % MOD;
      ak = ak * a % MOD;
    }
  }

  return sum;
}
\end{minted}

Pentru claritatea contractului, codul este puțin nenatural: valorile mici ale lui $i$ corespund la biți din stînga. Îl putem scurta dacă inversăm direcția lui $i$:

\begin{minted}{c}
int s(int a, int n) {
  int num_bits = 32 - __builtin_clz(n);
  long long sum = 0;
  long long ak = 1;

  for (int i = num_bits - 1; i >= 0; i--) {
    sum = (1 + ak) * sum % MOD;
    ak = ak * ak % MOD;

    if ((n >> i) & 1) {
      sum = (1 + a * sum) % MOD;
      ak = ak * a % MOD;
    }
  }

  return sum;
}
\end{minted}

\section{Divizibilitate}

Această secțiune este doar un ciot ca să reamintim următoarea complexitate. Suma armonică $n + \frac{n}{2} + \frac{n}{3} + ... + \frac{n}{n}$ este $\bigoh(n \log n)$. Vom vedea această egalitate folosită astfel: pentru toate valorile $k$ de la $1$ la $n$, putem să iterăm prin toți multiplii de $k$, iar complexitatea va fi $\bigoh(n \log n)$.

\section{Principiul includerii și excluderii}

Acest principiu nu are legătură directă cu teoria numerelor, dar survine adesea în probleme de divizibilitate. De aceea, pare un moment bun să îl abordăm. La nivelul acestui curs, principiul este cunoscut, dar îl reiau foarte pe scurt. Ocazional îl voi denumi prescurtat pinex (engl. \textit {PIE} sau \textit{inclusion-exclusion principle}).

Din teoria mulțimilor știm că

$$|A \cup B| = |A| + |B| - |A \cap B|$$

Iar pentru trei mulțimi,

$$ | A \cup B \cup C| = (|A| + |B| + |C|) - (|A \cap B| + |B \cap C| + |C \cap A|) + | A \cap B \cap C|$$

Pentru mai mult de trei mulțimi, desigur, regula generală este că luăm cu semnul $+$ intersecțiile de număr impar de mulțimi și cu semnul $-$ intersecțiile de număr impar de mulțimi.

Vom lua ca exemplu problema \href{https://cses.fi/problemset/task/2185}{Prime Multiples} (CSES), pe care o regăsiți și în \hyperref[problem:prime-multiples]{secțiunea de probleme}. Subliniem că numerele de la intrare sînt prime și distincte. De asemenea, numărul de numere între $1$ și $n$ divizibile cu un $x$ dat este de $\lfloor n/x \rfloor$. Atunci găsim soluția astfel:

\begin{enumerate}
  \item Adunăm numerele divizibile cu oricare număr prim.

  \item Scădem numerele divizibile cu orice pereche de numere prime (adică cu produsul perechii).

  \item Adunăm numerele divizibile cu orice triplet de numere prime.

  \item etc.
\end{enumerate}

Vedem adesea două implementări pentru acest principiu.

\subsection{Implementare iterativă}

Implementarea iterativă numără binar de la $1$ la $2^k - 1$. Fiecare dintre aceste valori corespunde unei combinații de numere prime. Valoarea este o mască în care biții 1, și doar aceia, indică numerele prime care participă în combinație. Pentru numerele prime $11, 7, 5, 3, 2$, masca $10110_{(2)}$ se referă la combinația $11 \times 5 \times 3$.

Această implementare are complexitatea  $\bigoh(2^k \cdot k)$, deoarece fiecare mască trebuie descompusă pentru a-i afla biții de 1.

\subsection{Implementare recursivă}

Implementarea recursivă construiește masca bit cu bit, cîte unul la fiecare nivel al recursivității. În fapt, nici nu mai transmitem ca parametru masca, ci direct produsul numerelor prime selectate pînă acum. La fiecare nivel putem să selectăm sau nu numărul curent, deci facem două apeluri recursive.

Avem nevoie și de numărul de numere selectate pînă acum. Dar de fapt, paritatea acestui număr ne ajunge. Pentru extra concizie, putem înmulți produsul curent cu -1 ori de cîte ori îl înmulțim cu un număr prim.

Această implementare are complexitate $\bigoh(2^k)$, semnificativ mai mică față de cea recursivă (pe CSES, 0,02 s față de 0,13 s).


\section{Indicatorul lui Euler}

În lumea programării competitive, multe probleme de calcul modular se referă la moduli primi. Aceasta se întîmplă din motivul, destul de tangențial, că majoritatea problemelor cer răspunsul modulo $10^9 + 7$ sau modulo altă valoare primă și de aceea avem nevoie să calculăm puteri, inverse, combinări etc. modulo acea valoare.

Dar vom da, acolo unde putem, și generalizări pentru moduli neprimi. Vom lua fără demonstrație unele dintre afirmații (știu că asta vă întristează peste măsură).

\begin{definition}[Indicatorul lui Euler]
Indicatorul lui Euler (engl. \href{https://en.wikipedia.org/wiki/Euler\%27s_totient_function}{Euler's totient function}) al unui număr $n$ este numărul de numere coprime cu $n$ cuprinse între $1$ și $n$. Îl notăm cu $\varphi(n)$.
\end{definition}

O formulă de calcul este:

$$\varphi(n) = n \prod_{p|n} \left(1 - \frac{1}{p}\right)$$

unde $p$ iterează prin divizorii primi ai lui $n$. În limbaj natural, pentru fiecare divizor prim $p$, eliminăm o fracție de $1/p$ din $n$, căci fiecare al $p$-lea număr se divide cu $p$ și deci nu este coprim cu $n$. Exemple:

\begin{itemize}
  \item Pentru orice număr prim, $\varphi(n) = n-1$, căci toate numerele de la $1$ la $n-1$ sînt coprime cu $n$.

  \item Pentru orice produs de numere prime distincte, $\varphi(pq) = (p-1)(q-1)$. Vezi tabelul următor.
\end{itemize}

\begin{itemize}
  \item Pentru orice produs de puteri de numere prime,
\end{itemize}
$$\varphi(n = p^a \cdot q^b) = n \cdot \frac{p-1}{p} \frac{q-1}{q}$$

Generalizînd la oricîți factori primi, rezultă a doua formulă din pagina Wikipedia. Mai exact, dacă $n = p_1^{k_1}p_2^{k_2} \dots p_r^{k_r}$, atunci

$$\varphi(n) = p_1^{k_1-1}(p_1 - 1) p_2^{k_2-1} (p_2 - 1) \dots p_r^{k_r-1} (p_r - 1)$$

\subsection{Calculul lui \texorpdfstring{$\varphi$}{phi}}

Calculul în $\bigoh(\sqrt{n})$ este absolut elementar. El ia fracția $(p-1)/p$ pentru prima apariție a unui factor prim $p$, apoi elimină din $n$ toate aparițiile lui $p$.

\begin{minted}{c}
int euler_totient(int n) {
  int phi = n;
  for (int p = 2; p * p <= n; p++) {
    if (n % p == 0) {
      phi = phi / p * (p - 1);
      while (n % p == 0) {
        n /= p;
      }
    }
  }
  if (n > 1) {
    phi = phi / n * (n - 1);
  }
  return phi;
}
\end{minted}

\subsection{Calculul lui \texorpdfstring{$\varphi$}{phi} de la \texorpdfstring{$1$}{1} la \texorpdfstring{$n$}{n}}

Putem folosi o metodă similară cu Ciurul lui Eratostene pentru a calcula toate valorile lui $\varphi$ de la $1$ la $n$:

\begin{minted}{c}
void compute_all_phi() {
  for (int i = 0; i <= MAX_N; i++) {
    phi[i] = i;
  }

  for (int i = 2; i <= MAX_N; i++) {
    if (phi[i] == i) {
      for (int j = i; j <= MAX_N; j += i) {
        phi[j] -= phi[j] / i;
      }
    }
  }
}
\end{minted}

Inițial, considerăm că fiecare număr este coprim cu toate numerele (inclusiv cu el însuși). Cînd considerăm un număr \ccode{i} pentru care încă avem egalitatea \ccode{phi[i] == i}, atunci \ccode{i} este prim. Doar pentru numerele prime, codul iterează prin toți multiplii și îi înmulțește cu \ccode{(i - 1) / i} (în practică, codul face o scădere pentru a evita o înmulțire). Rezultatul final este cel dorit: fiecare număr este înmulțit cu $\frac{p-1}{p}$ pentru fiecare factor prim $p$ al său.

Complexitatea este $O(n \log \log n)$, deoarece avem de-a face cu \href{https://en.wikipedia.org/wiki/Divergence_of_the_sum_of_the_reciprocals_of_the_primes}{suma inverselor numerelor prime}.
\section{Teorema lui Euler}

\href{https://en.wikipedia.org/wiki/Euler\%27s_theorem}{Teorema lui Euler} este o generalizare a Micii teoreme a lui Fermat. Dacă $a$ și $n$ sînt întregi coprimi, atunci

$$a^{\varphi(n)} \equiv 1 \pmod{n}$$

Recunoaștem cazul particular al Micii teoreme a lui Fermat, cînd $p$ era prim, iar $\varphi(p) = p - 1$. Rezultă că, pentru a calcula $a^b \mod n$, putem întîi să calculăm $\varphi(n)$ și să reducem exponentul $b$ modulo $\varphi(n)$.


\section{Algorithmul lui Euclid extins}

O cărămidă de bază în teoria numerelor este calcularea inverselor modulare. Majoritatea elevilor le calculează folosind exponențierea rapidă, și vom învăța și noi cum. Dar este bine să știți și algoritmul lui Euclid, deoarece acesta este mai rapid și funcționează indiferent dacă modulul este prim sau compus.

Algoritmul lui Euclid simplu primește două numere $a$ și $b$ și returnează $d = \text{cmmdc}(a, b)$. Algoritmul extins găsește, pe lîngă $d$, și două valori $x$ și $y$ pentru care

$$ax + by = d$$

Exemplu: $\text{cmmdc}(14, 35) = 7$. Algoritmul lui Euclid va găsi și valorile $x = -2$ și $y = 1$ cu care

$$14 \cdot (-2) + 35 \cdot 1 = 7$$

Pentru cei pasionați de matematică, \href{https://en.wikipedia.org/wiki/B\%C3\%A9zout's_identity}{Identitatea lui Bézout} demonstrează că aceste valori există. Valorile nu sînt unice. Alte valori posibile sînt $14 \cdot 3 + 35 \cdot (-1) = 7$ sau $14 \cdot 8 + 35 \cdot (-3) = 7$.

\subsection{Implementarea recursivă}

Ca și algoritmul lui Euclid simplu, și cel extins reduce problema $(a,b)$ la problema $(b,r)$. Fie $a = qb + r$. Odată ce am găsit $x'$ și $y'$ care satisfac $bx' + ry' = d$, cum calculăm $x$ și $y$? Nu este greu; doar îl înlocuim pe $r$ cu $a - qb$:

\begin{align*}
  d &= bx' +ry' \\
    &= bx' + (a - qb)y' \\
    &= a(y') + b(x' - qy')
\end{align*}

, de unde rezultă coeficienții lui $a$ și $b$, respectiv $y'$ și $x' - qy'$.

\begin{minted}{c}
void extended_euclid_recursive(int a, int b, int& d, int& x, int& y) {
  if (!b) {
    d = a;
    x = 1;
    y = 0;
  } else {
    int xp, yp;
    extended_euclid_recursive(b, a % b, d, xp, yp);
    x = yp;
    y = xp - (a / b) * yp;
  }
}
\end{minted}

\subsection{Implementarea iterativă}

Varianta iterativă este mai alunecoasă și nu este cu mult mai rapidă. O prezentăm doar ca experiment de gîndire. Fie $A$ și $B$ valorile inițiale. Implementarea distruge valorile $a$ și $b$, înlocuindu-le după cum știm cu $b$ și $a \mod b$. Concomitent, ea menține patru valori $x, y, x', y'$ cu invariantul că, la orice moment:

\begin{equation}
  \left\{
  \begin{aligned}
    Ax &+ By &= a\\
    Ax' &+ By' &= b
  \end{aligned}
  \right.
\end{equation}

Inițial, $A = a$ și $B = b$, deci $x = 1$, $y = 0$, $x' = 0$ și $y' = 1$. Știm că la finalul algoritmului $a = d$ și $b = 0$, deci valorile pe care trebuie să le returneze algoritmul sînt valorile finale pentru $x$ și $y$. Pentru menținerea invariantului, știm că dorim să înlocuim perechea $(a, b)$ cu $(b, r)$. Cu ce trebuie să înlocuim sistemul de ecuații? Să scriem:

$$
\begin{aligned}
  a &- qb &= r\\
  (Ax + By) &- q(Ax' + By') &= r\\
  A(x - qx') &+ B(y - qy') &= r
\end{aligned}
$$

Așadar, noul sistem de ecuații este:

\begin{equation}
  \left\{
  \begin{aligned}
    Ax' &+ By' &= b\\
    A(x - qx') &+ B(y - qy') &= r
  \end{aligned}
  \right.
\end{equation}

Și rezultă înlocuirile $(x, x') \to (x', x - qx')$ și $(y, y') \to (y', y - qy')$.

\begin{minted}{c}
void extended_euclid_iterative(int a, int b, int& d, int& x, int& y) {
  x = 1;
  y = 0;
  int xp = 0, yp = 1;
  while (b) {
    int q = a / b;
    int tmp = b; b = a - q * b; a = tmp;
    tmp = xp; xp = x - q * xp; x = tmp;
    tmp = yp; yp = y - q * yp; y = tmp;
  }
  d = a;
}
\end{minted}

Ca și algoritmul simplu, cel extins se oprește cînd $b = 0$, iar atunci c.m.m.d.c.-ul este $a$ (ultimul rest obținut).


\section{Inverse modulare}

Dorim să calculăm inversul lui $a$ modulo un număr $M$, adică să găsim un număr $b$ astfel încît

$$a \cdot b \equiv 1 \pmod{M}$$

Reamintesc că inversul există dacă și numai dacă $a$ și $M$ sînt coprime. Altfel, dacă $\text{cmmdc}(a, M) = d > 1$, orice „invers” $b$ am propune vom observa că $ab \pmod M > 1$, căci se divide cu $d$.

\subsection{Prin exponențiere rapidă}

Din teorema lui Fermat rezultă imediat că

$$a^{M-2} \equiv a^{-1} \pmod{M}$$

Așadar, putem calcula inversul $a^{-1}$ prin exponențiere rapidă. Acest mecanism funcționează doar cînd modulul $M$ este prim. Cînd modulul este compus este nevoie să calculăm indicatorul lui Euler și să folosim formula:

$$a^{\varphi(M)-1} \equiv a^{-1} \pmod{M}$$

Trebuie să facem acest lucru chiar și dacă $a$ este coprim cu $M$. De exemplu, inversul lui $a = 5$ modulo $M = 14$ este $3$, căci $5 \cdot 3 = 15 \equiv 1 \pmod{14}$. În schimb, $5^{14-2} = 5^{12} \equiv 1 \pmod{14}$, incorect. Este nevoie să calculăm $\varphi(14) = 6$ și $5^5 = 3125 \equiv 3 \pmod{14}$.

\subsection{Prin algoritmul lui Euclid extins}

Din algoritmul lui Euclid decurge o metodă imediată de calcul al inverselor. Inversul lui $a$ modulo $n$ este valoarea $b$ pentru care

$$ab \equiv 1 \pmod{M} \implies ab + kM = 1$$

Apelînd algoritmul lui Euclid extins între $a$ și $M$ îl aflăm pe $b$ (și, ca produs secundar, pe $k$). Observăm din nou că $a$ are invers dacă și numai dacă este coprim cu $M$. Dacă $\text{cmmdc}(a, M) = d > 1$, atunci combinația liniară $ab + kM$ va fi întotdeauna multiplu de $d$, niciodată 1.

Atenție: algoritmul poate returna un invers negativ. Dacă este așa, adăugați-i $M$ pentru a-l aduce în intervalul $[1, M)$.

\subsection{Relația cu principiul includerii și excluderii}

Soluția bazată pe pinex este următoarea. Examinăm succesiv numerele și, pentru fiecare număr $x$, ne propunem să aflăm cu cîte numere examinate anterior este el coprim. Suma acestor răspunsuri este răspunsul la problemă.

Pentru a afla răspunsul pentru $x$, întîi îl factorizăm pe $x$ (construim ciurul ca să factorizăm rapid toate numerele). Apoi, de exemplu, dacă $x=14$, el va fi coprim:

\begin{itemize}
  \item cu toate numerele anterioare;
  \item minus cele anterioare divizibile cu 2;
  \item minus cele anterioare divizibile cu 7;
  \item plus cele anterioare divizibile cu 14.
\end{itemize}

\subsection{Definiția funcției Möbius}

Haideți acum, în loc să contorizăm contribuția fiecărui număr, să contorizăm contribuția fiecărui divizor. Ar fi bine ca totalul general să fie același. \emoji{slightly-smiling-face} Să considerăm divizorul 14. Ori de cîte ori examinăm un multiplu de 14 (cum ar fi 14, 28 sau 70), în cursul pinex vom procesa și divizorul 14. El va contribui întotdeauna cu semnul +, căci are un număr par de factori primi distincți. La primul multiplu de 14 el va adăuga 0 (căci nu există anterior alți multipli de 14). La al doilea va adăuga 1, apoi 2, apoi 3 etc. Așadar, contribuția unui divizor $d$ va fi o sumă Gauss luată cu un semn anume:

$$\mu(d) \times \frac{M(d)(M(d) - 1)}{2}$$

Cu $M(d)$ am notat numărul de multipli de $d$ printre cele $n$ numere date, iar $\mu$ este funcția Möbius, care ne va spune cu ce semn trebuie să luăm contribuția. Pentru a-l calcula pe $M(d)$ pentru toți divizorii $d$, ne reamintim de suma armonică. Așadar, ne permitem să calculăm frecvențele numerelor de la intrare, apoi să însumăm frecvențele tuturor multiplilor lui $d$, pentru fiecare $d$.

Acum putem să iterăm prin toți divizorii de la 1 la $MAX\_VAL$ și să însumăm contribuția lor. Dar trebuie să aflăm rapid pe care îi luăm cu $+$, pe care cu $-$ și pe care îi omitem, căci conțin factori repetați (cum ar fi $18 = 2 \cdot 3 \cdot 3$).

Am ajuns în sfîrșit la \href{https://en.wikipedia.org/wiki/M\%C3\%B6bius_function}{Funcția Möbius}, notată cu $\mu(x)$. Ea definește exact cantitatea care ne interesează în această problemă, respectiv:

\begin{itemize}
  \item $+1$ dacă $x$ este liber de pătrate și are un număr par de factori primi.

  \item $-1$ dacă $x$ este liber de pătrate și are un număr impar de factori primi.

  \item $0$ dacă $x$ nu este liber de pătrate (adică se divide cu un pătrat perfect).
\end{itemize}

\subsubsection*{Metoda 1}

Metoda 1 calculează, în primă fază, în $u[i]$ produsul divizorilor primi ai lui $i$, mai mici sau egali cu $\sqrt{n}$, cu semnul + dacă există un număr par de divizori primi sau - în caz contrar. Concomitent, atribuie $u[i] = 0$ pentru toate valorile $i$ care se divid cu un pătrat perfect. De exemplu $u[6] = 6$, $u[42] = -42$, $u[18] = 0$.

Ce valori nenule putem întîlni la final?

\begin{itemize}
  \item Fie $u[i] = \pm i$, caz în care $\mu[i]$ este exact semnul lui $u[i]$,

  \item fie $u[i] \neq \pm i$, caz în care $i$ mai are un factor prim, mai mare decît $\sqrt{n}$, deci $\mu[i]$ are semn opus lui $u[i]$.
\end{itemize}

\begin{minted}{c}
// Învățat de la https://mathoverflow.net/a/99545
void compute_mobius(int n) {
  for (int i = 1; i <= n; i++) {
    u[i] = 1;
  }

  for (int i = 2; i * i <= n; i++) {
    if (u[i] == 1) {
      for (int j = i; j <= n; j += i) {
        u[j] *= -i;
      }
      for (int j = i * i; j <= n; j += i * i) {
        u[j] = 0;
      }
    }
  }

  for (int i = 2; i <= n; i++) {
    if (u[i] == i) {
      u[i] = 1;
    } else if (u[i] == -i) {
      u[i] = -1;
    } else if (u[i] < 0) {
      u[i] = 1;
    } else if (u[i] > 0) {
      u[i] = -1;
    }
  }
}
\end{minted}

Complexitatea este $\bigoh(n \log \log n)$. Ne reîntîlnim cu suma inverselor numerelor prime.

\subsubsection*{Metoda 2}

Metoda 2 este cea din \hyperref[code:counting-coprime-pairs]{sursa anexată}. Ea folosește un ciur cu cel mai mic factor și tratează școlărește cele trei cazuri de mai sus.

\begin{minted}{c}
// Adaptat după https://www.geeksforgeeks.org/program-for-mobius-function-set-2/
void compute_smallest_factors(int n) {
  factor[1] = 1;
  for (int i = 2; i <= n; i++) {
    if (!factor[i])  {
      for (int j = i; j <= n; j += i) {
        if (!factor[j]) {
          factor[j] = i;
        }
      }
    }
  }
}

void compute_mobius(int n) {
  u[1] = 1;
  for (int i = 2; i <= n; i++) {
    if (factor[i] == factor[i / factor[i]]) {
      u[i] = 0;
    } else {
      u[i] = -u[i / factor[i]];
    }
  }
}
\end{minted}

\subsubsection*{Metoda 3}
\label{subsubseq:mobius-method-3}

Pe aceasta am învățat-o de la \href{https://kilonova.ro/submissions/84735}{Mircea Rebengiuc}! Ea este considerabil mai lentă pentru $n$ foarte mare. Dar pentru valori practice ($n \leq \np{1000000}$), diferențele sînt neglijabile.

\begin{minted}{c}
void compute_mobius(int n) {
  u[1] = 1;
  for (int i = 1; i <= n; i++) {
    if (u[i]) { // optional speed optimization
      for (int j = 2 * i; j <= n; j += i) {
        u[j] -= u[i];
      }
    }
  }
}
\end{minted}

Cum funcționează? Putem da și o demonstrație combinatorică. De exemplu, pentru $i = 30$, valorile care vor contribui la $u[30]$ vor fi $u[2]$, $u[3]$ și $u[5]$ cu semnul + și $u[1]$, $u[6]$, $u[10]$ și $u[15]$ cu semnul -. Rezultat: -1. Presupunînd că $i$ are $f$ factori primi, și considerînd toate submulțimile acestor factori, vom obține suma

$$u[i] = \sum_{k=0}^{f-1} C_f^k \cdot (-1)^k$$

Această sumă coincide cu dezvoltarea binomială a lui $(1 - 1)^f$, cu excepția ultimului termen. Ea va avea valoarea $\pm 1$ în funcție de paritatea lui $f$.

O explicație mult mai elegantă pornește de la egalitatea $\sum_{d|n} \mu(d) = 0$ (pentru $n > 1$), pe care o vom studia în secțiunea despre formula de inversiune Möbius.

\section{Formula de inversiune Möbius}

Această secțiune este mai mult teoretică.

\subsection{Funcția Möbius este multiplicativă}

Să demonstrăm întîi că funcția Möbius este multiplicativă, adică $\mu(1) = 1$ și $\mu(mn) = \mu(m)\mu(n)$ pentru orice valori $m$ și $n$ \textbf{coprime} (acest aspect este important).

Voi urma \href{https://math.stackexchange.com/a/895388}{această demonstrație}. Dacă fie $m$ fie $n$ \textbf{nu} sînt libere de pătrate, atunci nici $mn$ nu va fi liber de pătrate. Atunci fie $\mu(m)$, fie $\mu(n)$ vor fi 0, iar $\mu(mn)$ va fi tot 0. Deci se verifică egalitatea $\mu(mn) = \mu(m)\mu(n)$.

Altfel, $m$ și $n$ sînt libere de pătrate și coprime. Atunci $m$ este un produs de $k$ factori primi distincți, iar $n$ este un produs de \textbf{alți} $l$ factori primi distincți. Rezultă că $mn$ este un produs de $k+l$ factori primi distincți (și liber de pătrate). Deci avem pe de o parte că $\mu(mn) = (-1)^{k+l}$, iar $\mu(m)\mu(n) = (-1)^k (-1)^l$, deci din nou se verifică egalitatea $\mu(mn) = \mu(m)\mu(n)$.

\subsection{Suma funcției Möbius peste divizori este multiplicativă}

Mai facem un pas către inversiunea Möbius și introducem funcția

$$f(n) \triangleq \sum_{d|n} \mu(d)$$

Să demonstrăm că și această funcție este multiplicativă. Clar, $f(1) = 1$ deoarece 1 are un singur divizor și $\mu(1) = 1$. Acum, fie două numere coprime $m$ și $n$. Orice divizor $d$ al lui $mn$ poate fi scris ca produs dintre un divizor $d_1$ al lui $m$ și unul $d_2$ al lui $n$. Mai mult, deoarece $m$ și $n$ sînt coprime, și divizorii $d_1$ și $d_2$ vor fi coprimi, așadar $\mu(d_1 d_2) = \mu(d_1) \mu(d_2)$. Punînd totul cap la cap obținem:

\begin{align*}
f(mn) &= \sum_{d|mn} \mu(d) \\
&= \sum_{d_1 | m,\ d_2 | n} \mu(d_1 d_2) \\
&= \sum_{d_1 | m,\ d_2 | n} \mu(d_1) \mu(d_2) \\
&= \sum_{d_1|m} \sum_{d_2|n} \mu(d_1)\mu(d_2) \\
&= \Big( \sum_{d_1|m} \mu(d_1) \Big) \cdot \Big( \sum_{d_2|n} \mu(d_2) \Big) \\
&= f(m) f(n)
\end{align*}

\subsection{Valoarea sumei funcției Möbius peste divizori}

Să demonstrăm egalitatea:

$$
f(n) \triangleq \sum_{d|n} \mu(d) =
\begin{cases}
1 & \textrm{dacă} \; n = 1\\
0 & \textrm{dacă} \; n > 1
\end{cases}
$$

Desigur, dacă $n = 1$, singurul divizor este $1$, iar $\mu(1) = 1$.

\subsubsection*{Demonstrație cu combinatorică}

Dacă $n$ nu este liber de pătrate, atunci el va avea și divizori neliberi de pătrate. Aceia vor avea $\mu(d) = 0$ și îi putem ignora la sumă. Așadar, în $f(n)$ putem ține cont doar de divizorii lui $n$ liberi de pătrate, adică putem lua în calcul doar factorii primi ai lui $n$ la puterea 1. De exemplu, pentru $n = 84 = 2^2 \cdot 3 \cdot 7$ putem calcula efectiv suma pentru $n' = 2 \cdot 3 \cdot 7 = 42$.

Dacă $n$ este liber de pătrate și constă din $r$ factori primi, atunci pentru fiecare $k = 0, 1, \dots, r$ vor exista $C_r^k$ moduri de a forma divizori cu $k$ dintre factorii primi, iar toți acei divizori vor avea $\mu = (-1)^k$. De aceea,

$$f(n) = \sum_{k=0}^{r} C_r^k \cdot (-1)^k = (1 + (-1))^r = 0$$

\subsubsection*{Demonstrație pornind de la multiplicativitatea lui \texorpdfstring{$f$}{f}}

Dacă $n$ are forma $n = p^k$ pentru un număr prim $p$ și $k \geq 1$, atunci divizorii lui $n$ sînt $1, p, p^2, \dots, p^k$. Știm că $\mu(1) = 1$, $\mu(p) = -1$, iar pentru exponenți $e \geq 2$, $\mu(p^e) = 0$ pentru că acei divizori nu sînt liberi de pătrate. Deci $f(n) = 1 + (-1) + 0 + \dots + 0 = 0$.

În cazul general, fie $n = p_1^{k_1} \cdot p_2^{k_2} \cdot\dots \cdot p_r^{k_r}$. Atunci:

\begin{align*}
f(n) &= f(p_1^{k_1} \cdot p_2^{k_2} \cdot \dots \cdot p_r^{k_r}) \\
&= f(p_1^{k_1}) \cdot f(p_2^{k_2}) \cdot \dots \cdot f(p_r^{k_r}) \\
&= 0 \cdot 0 \cdot \dots \cdot 0 \\
&= 0
\end{align*}

\subsubsection*{Corolar: Calculul funcției Möbius}

Acum înțelegem \hyperref[subsubseq:mobius-method-3]{metoda 3} de calcul al funcției Möbius. Pornind de la funcția $f$, ea definește

$$\mu(n) = -\sum_{d|n,\ d \neq n} \mu(d)$$

\subsection{Formula de inversiune a lui Möbius}

Acum avem tot ce ne trebuie ca să demonstrăm \href{https://en.wikipedia.org/wiki/M\%C3\%B6bius_inversion_formula}{Formula de inversiune a lui Möbius}. O reluăm și aici. Dacă $f$ și $g$ sînt două funcții care satisfac relația

$$g(n) = \sum_{d|n} f(d) \ \textrm{pentru}\ n \geq 1$$

atunci

$$f(n) = \sum_{d|n} \mu(d) g\Big(\frac{n}{d}\Big) \ \textrm{pentru}\ n \geq 1$$

Vom urma \href{https://math.stackexchange.com/q/1757352}{demonstrația aceasta} și primul răspuns. Pornim de la formula lui $f$ în care facem schimbarea de notație $d \to n/d$:

$$\sum_{d|n} \mu(d) g\Big(\frac{n}{d}\Big) = \sum_{d|n} \mu\Big(\frac{n}{d}\Big) g(d)$$

Aici îl înlocuim pe $g$ conform ipotezei date:

$$\sum_{d|n} \mu(d) g\Big(\frac{n}{d}\Big) = \sum_{d|n} \Biggl(\mu\Big(\frac{n}{d}\Big) \sum_{d'|d} f(d')\Biggr)$$

Exprimăm această sumă de perechi sub altă formă:

$$\sum_{d|n} \mu(d) g\Big(\frac{n}{d}\Big) = \sum_{d'|d|n} f(d') \mu\Big(\frac{n}{d}\Big)$$

Așadar, ne pregătim să-l trecem pe $d'$ în exterior. Acum, pentru un $d'$ fixat, ce valori poate lua $n/d$? Deoarece $d'|d$, rezultă că $(n/d) | (n/d')$. Facem notația $m = n/d$ și ajungem la:

$$\sum_{d|n} \mu(d) g\Big(\frac{n}{d}\Big) = \sum_{d'|n} f(d') \sum_{m|\frac{n}{d'}}\mu(m)$$

În partea dreaptă recunoaștem suma funcției Möbius peste divizorii lui $n/d'$. Iau naștere două cazuri.

\begin{enumerate}
  \item Cînd $d' = n$, suma din dreapta iterează prin divizorii lui 1. Știm că valoarea acelei sume este 1.

  \item Cînd $d' < n$, atunci $n/d' > 1$, deci suma din dreapta este 0.
\end{enumerate}

Rezultă, în sfîrșit, că:

$$\sum_{d|n} \mu(d) g\Big(\frac{n}{d}\Big) = f(n) \cdot 1 + \sum_{d'|n,\ d < n} f(d') \cdot 0 = f(n)$$

\subsection{Aplicații}

Spre șocul meu, nu am găsit aplicații directe ale acestei formule. Invariabil am descoperit că toate problemele pe care le rezolvă inversiunea Möbius pot fi rezolvate și direct cu funcția Möbius sau chiar mai elementar. Iată totuși cîteva exemple.

\subsubsection*{Numărul de divizori}

Dacă alegem $f(n) = 1$, atunci $g(n) = \sum_{d|n} f(d)$ este numărul de divizori ai lui $n$. Prin inversiunea Möbius obținem că:

$$\sum_{d|n} \mu(d) g\Big(\frac{n}{d}\Big) = 1$$

Exemplu: Pentru $n = 10$, divizorii săi sînt 1, 2, 5 și 10, care au respectiv 1, 2, 2 și 4 divizori. Obținem că

$$\mu(1) g(10) + \mu(2) g(5) + \mu(5) g(2) + \mu(10) g(1) = 1 \cdot 4 - 1 \cdot 2 - 1 \cdot 2 + 1 \cdot 1 = 1$$

Putem folosi inversiunea Möbius ca să calculăm $g(k)$ = numărul de divizori ai lui $k$ pentru fiecare valoare $1 \leq k \leq n$ dacă separăm unul dintre termenii sumei:

$$g(n) = \mu(1) \cdot g\Big(\frac{n}{1}\Big) = 1 - \sum_{d|n,\ d \neq 1} \mu(d) g\Big(\frac{n}{d}\Big)$$

Putem implementa această formulă: fiecare divizor contribuie la numărul de divizori ai fiecărui multiplu al său. Dar... noi am făcut deja fix acest lucru în problema \hyperref[problem:counting-divisors]{Counting Divisors}.

\subsubsection*{Suma divizorilor}

Similar, dacă alegem $f(n) = n$, atunci $g(n) = \sum_{d|n} f(d)$ este suma divizorilor lui $n$, notată cu $\sigma(n)$, despre care am vorbit la problema \hyperref[problem:sum-of-divisors]{Sum of Divisors}. Prin inversiunea Möbius obținem că:

$$\sum_{d|n} \mu(d) \sigma\Big(\frac{n}{d}\Big) = n$$

Ca și în exemplul anterior, putem calcula $\sigma(k)$ pentru toate valorile $1 \leq k \leq n$, dar știm deja să facem acest lucru fără să folosim inversiunea Möbius.

\subsubsection*{Numărul de perechi coprime}

Vom urma Exemplul 1 din \href{https://codeforces.com/blog/entry/53925}{acest articol de pe Codeforces}. Dat fiind $n$, trebuie să numărăm perechile coprime $(x,y) \in [1, n] \times [1,n]$. Cerința seamănă cu problema \hyperref[problem:playing-with-gcd]{Playing with GCD}, cu trei diferențe:

\begin{enumerate}
  \item Trebuie să calculăm perechile coprime în loc de necoprime.
  \item Trebuie să includem și perechile neordonate, adică $x > y$.
  \item Trebuie să aflăm răspunsul doar pentru un $n$ dat, nu pentru toate $1 \leq k \leq n$.
\end{enumerate}

Soluția la Playing with GCD era o sumă de valori $\varphi$. Inversiunea Möbius duce la o soluție diferită, care însă calculează răspunsul pentru un singur $n$.
